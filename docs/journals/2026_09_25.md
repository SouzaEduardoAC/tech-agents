# V3 Playbook Expansion & PO Elicitation Protocol Upgrade
- **Requirements Elicitation Deepening**:
	- Analyzed the disparity between the legacy `/po:squad-discovery` command (which jumped directly to drafting a PRD in one shot) versus the rich 5-phase interactive elicitation protocol of `/po:interview`.
	- Centralized engineering standards into root `knowledge/`:
		- `knowledge/product_interview.md`: Formally documents the 5-phase elicitation loop (Problem & Value, Scope & Journeys, Integrations & Data, Financials/RICE, and Success Metrics).
		- `knowledge/gatekeeping.md`: Mandates constructive friction, distinguishing between Strategic Notes (soft friction, proceed with alternative) and Halt Conditions (hard friction, refuse PRD on critical variable voids).
	- Upgraded `lenses/po.md` to demand active variable probing, elimination of vagueness, and Given-When-Then acceptance criteria with lean MoSCoW scoping.
	- Enriched Step 1 (`discovery`) in `playbooks/feature_dev.yaml` to reference both standards.

- **Dialectical Debate Playbook (`playbooks/council_debate.yaml`)**:
	- Migrated the structured workload of the Council meta-debate into a deterministic 3-step state machine:
		1. `thesis`: Architectural Thesis & Technical Rationale (Architect lens, auth standards, `{{args}}-debate-thesis.md`).
		2. `antithesis`: Critical Antithesis & Risk Audit (Compliance lens, regulations & soc2 standards, `{{args}}-debate-antithesis.md`).
		3. `synthesis`: Strategic Synthesis & ADR Formulation (Council lens, `adr_schema.json` verification, `{{args}}-adr.md`, gated by `council_synthesis`).

- **Codebase Health Audit Playbook (`playbooks/codebase_health_audit.yaml`)**:
	- Consolidated multi-agent static analysis and diagnostic commands into a deterministic 3-step pipeline:
		1. `static_analysis`: Code Quality & Static Analysis (Architect lens, hard checks running auto-detected test & lint runners, `health-static-analysis.md`).
		2. `security_compliance`: Security & Dependency Vulnerability Scan (Compliance lens, licensing, soc2, and gdpr standards, `health-security-audit.md`).
		3. `remediation_plan`: Prioritized Tech Debt & Remediation Plan (QA lens, `codebase-health-report.md`, gated by `health_report`).

- **Verification & Parity**:
	- Created dedicated integration test suite `test/v3-council-and-health-test.js` validating the state transitions, gate blockages, check executions, and completion of both new playbooks.
	- Updated Phase 2, Phase 3, Phase 5, and Phase 6 test suites to validate all 11 playbooks, 11 lenses, and centralized knowledge files.
	- 100% test pass rate across all 11 test suites.

# Standalone PM Discovery, Technical Refinement & Scaffolding Playbooks
- **Role-Based Workflow Decoupling**:
	- Acknowledged real-world user archetypes who do not run full 7-step code implementation pipelines: Product Managers creating backlog tickets (Azure Boards, Jira, Linear) and Tech Leads conducting technical refinement meetings.
	- Created `playbooks/product_discovery.yaml`: 2-step standalone PRD workflow (`elicitation_interview` -> `prd_formulation` with schema validation and `prd` approval gate) producing clean user stories and acceptance criteria without triggering code generation.
	- Created `playbooks/technical_refinement.yaml`: 2-step Tech Lead workflow (`codebase_feasibility` -> `implementation_plan` with ADR schema validation and `plan` approval gate) analyzing architectural constraints, dependencies, and task breakdown.
	- Created `playbooks/component_scaffold.yaml`: 2-step developer workflow (`spec` -> `implement_and_test` with hard checks for tests/linters and `execution` approval gate) for rapid isolated component creation.
- **Logseq Knowledge Graph Housekeeping**:
	- Updated `docs/pages/Forge.md` to `status:: [DEPRECATED] (Replaced by V3 Declarative Playbooks & Cognitive Lenses)` with clear migration notice.
	- Updated `docs/pages/tech-agents-graph.md`: registered `[[Quicky]]` and `[[Council]]` under Specialized Agents, and updated `[[Forge]]` to deprecated.
- **Verification**:
	- Created dedicated test suite `test/v3-pm-refinement-test.js` validating all 3 workflows in isolated temporary git workspace.
	- 100% test pass rate across all 12 test suites (14 playbooks total).

# First-Class Peer MCP Toolboxes & Context7 Integration
- **Host-Level External MCP Bridging**:
	- Re-anchored external host MCP tools (Context7, Stitch, Playwright, SonarQube) into V3's Scoped Toolboxes (`engine/toolboxes.js`).
	- Defined explicit scope constraints:
		- `context7`: Library and API documentation lookups (`query-docs`, `resolve-library-id`). Restricted to discovery, analysis, and architecture phases.
		- `stitch`: UI/UX design tokens, design systems, and screen generation. Bound to discovery and frontend scaffold/implementation.
		- `playwright`: Headless browser testing, DOM verification, and interactive UI checks. Bound to implementation and acceptance validation.
		- `sonarqube`: Static code analysis, security hotspots, and quality gates. Bound to PR review and codebase health auditing.
- **Anti-Hallucination & Documentation Discipline**:
	- Enforced `knowledge/anti_hallucination.md` (Context7 Planning Directive) across `feature_dev`, `technical_refinement`, `component_scaffold`, and `deep_research`.
	- Mandated querying Context7 exclusively during planning/research steps to fetch verified real-world signatures, while keeping implementation steps zero-latency.
